# Архитектура мобильной редакции

## Границы

Мобильное приложение — самостоятельный нативный модуль в общем репозитории. Оно не
запускает FastAPI/Python desktop-части и не пытается переносить desktop SQLite-файл.
Общая точка будущей экосистемы — стабильная предметная модель и `.bwlbook`.

```text
MainActivity / platform Views
          │
          ├── BookRepository ── SQLiteOpenHelper
          │        │
          │        └── books / chapters / narration_jobs / audio_assets / logs
          │
          ├── NarrationService (foreground + wake lock)
          │        └── SpeechEngine: Android TextToSpeech
          │                 └── PCM callbacks ── StreamingWavWriter
          │
          ├── MediaPlayer + WaveformView
          └── BookPackageCodec ── SAF streams ── .bwlbook ZIP
```

UI читает и изменяет данные только через `BookRepository`. Задание озвучки содержит
снимок текста, голоса и настроек: правки редактора во время работы не могут незаметно
изменить уже начатое аудио. `sourceHash` позволяет отметить устаревшую версию.

## Состояния озвучки

```text
queued → running → finalizing → done
             │          │
             ├──────────┴──→ failed
             ├─────────────→ cancelled
             └─────────────→ interrupted → running (resume)
```

Длинный текст детерминированно режется по абзацам, предложениям и словам не длиннее
`TextToSpeech.getMaxSpeechInputLength()`. Фрагменты синтезируются строго по одному.
`onAudioAvailable` дописывает PCM в `.part`; после `onDone` репозиторий фиксирует
номер фрагмента и длину подтверждённых данных. При повторном старте хвост после
последней контрольной точки отрезается.

Финализация валидирует единый sample rate/encoding/channel count, дописывает RIFF/WAV
заголовок во временный файл и делает атомарное перемещение в постоянный каталог.
Только затем создаётся `AudioAsset`. Отмена останавливает TTS, закрывает writer и не
публикует частичный файл.

`NarrationService` стартует только из видимого пользовательского действия. Он сразу
вызывает `startForeground`, держит частичный wake lock, обновляет уведомление и БД,
а UI перечитывает активное задание при `onResume`. Поэтому Activity можно свернуть
или пересоздать независимо от работы синтезатора.

## Расширяемость

- UUID и `revision` принадлежат сущностям, а не строкам локальной SQLite.
- Медиа хранится отдельными `AudioAsset` с hash снимка и настройками голоса.
- `BookPackageCodec` работает с потоками `ContentResolver`, поэтому тем же контрактом
  можно питать USB, Nearby Share, облачный диск или LAN endpoint.
- Будущий `SyncGateway` обменивается manifest/entity revisions и tombstones; файл БД
  никогда не синхронизируется целиком.
- Следующий аудиокодек можно добавить за границей writer (MediaCodec AAC/M4A), не
  меняя книги, главы, задания и UI.

## Отказоустойчивость и ограничения

- Технический лог ограничен кольцевым буфером в SQLite.
- На каждом TTS callback проверяются формат, отмена и лимит классического RIFF.
- Перед синтезом проверяется доступное место с запасом; `.part` остаётся только для
  системно прерванного задания, но удаляется при явной отмене/ошибке формата.
- OEM TTS может не предоставлять PCM callbacks. Это диагностируется и показывается
  как техническая ошибка вместо выдачи битого «готового» файла.
